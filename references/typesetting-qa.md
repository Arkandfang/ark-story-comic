# 排字与 QA

## 先选排字模式

默认稳定流程是：先制作空白气泡和空白道具的原画，再由 SVG 或其他可控矢量文字层加入最终文字。这样可以冻结原画、精确换行并保留可修改性。

用户明确希望由图像编辑模型直接写字时，可以切换直接排字。它仍是“无字原画 → 定点文字编辑”的两阶段流程，不是把内容、画面和文字一次生成。两种模式共用同一份气泡主体、形状、安全框和实体框数据。

## 气泡测量

每只气泡至少记录：

- `bubble`：去掉尾巴后的真实主体矩形；
- `shape`：主体形状，使用 `ellipse` 或 `rect`；
- `box`：向内收缩后的文字安全框；
- `lines`：人工控制的分行；
- `max_size/min_size`：允许字号范围；
- `min_clearance`：文字到主体边界的最小距离。

不要把气泡尾巴计入主体中心。手绘气泡优先测量能够完整落在白色主体内的保守椭圆；如果无法近似，就扩／重画气泡，不能把形状谎报成矩形绕过审计。

必须同时通过：

1. 安全框位于气泡主体外接矩形内；
2. 最终字形像素包围框位于安全框内；
3. 椭圆气泡的字形包围框四角位于内缩椭圆内，矩形气泡与四边保留最小边距；
4. 文字中心与主体中心偏差不超过布局设定的容差；
5. 联系表人工确认文字未压线、未落入尾巴、未遮挡画面且没有明显视觉偏心。

阈值应随输出尺寸调整。布局未显式设置时，脚本按画布短边相对基准缩放默认字号、边距和中心容差。文字放不下时依次尝试：精简文字、重新分行、扩大／重画气泡，最后才降低字号。

## 非气泡文字

屏幕、卡片、地图、行程表、路牌和拟声字等需要记录：`frame` 实体边界、`box` 文字安全框、旋转角度、对齐方式和最小边距。表格行、便签或多个独立字段应分别测量，不能用整张道具的大框掩盖局部越界。

## 自动审计产物

渲染或直接排字审计至少输出：

- `qa/bubble-layout-audit.json` 与 `.md`；
- `qa/bubble-contact-sheet.jpg`；
- `qa/framed-text-layout-audit.json` 与 `.md`；
- `qa/framed-text-contact-sheet.jpg`；
- `qa/review-preview-pages/`；
- `qa/review-contact-sheet.jpg`。

审计数量必须与布局声明一致；ID 不得重复；任一项失败都应使命令非零退出。JSON 中每只气泡至少保存 `shape`、`bubble`、`safeBox`、`textBounds`、最小边距和中心偏差。

## 图像编辑模型直接排字门禁

编辑说明必须逐只声明所在页和画格、尾巴指向、精确文本、强制分行、对齐方式、四周留白和允许修改的区域。不要只说“把下面的字加进去”。

生成后运行：

```bash
node scripts/audit_direct_lettering.cjs \
  --root /absolute/path/to/direct-lettering-final \
  --source-root /absolute/path/to/source-final \
  --layout /absolute/path/to/direct-lettering-final/comic-layout.json
```

脚本将原画与成片归一到布局尺寸，通过差分提取新增深色文字像素，并检查：

- 检测到足够的新文字墨迹；
- 墨迹没有越过气泡主体或实体框；
- 超出内缩形状的比例不超过布局容差；
- 文字墨迹中心没有超过布局设置的偏差；
- 原画与成片尺寸符合布局。

差分审计不能证明文字内容正确，也不能证明允许区域之外完全没有被重绘。`visual-review.md` 仍须记录逐字核对、气泡联系表、冻结区对照和目标尺寸预览结果。任一项失败都不得交付。

## 视觉 QA

先逐页检查原尺寸：

- 气泡尾巴指向正确主体；
- 阅读顺序自然；
- 文字不压边、不遮挡关键画面、不跨格；
- 道具文字跟随道具角度；
- 伪文字已清除；
- 人物、主体、场景、时间和关键物件连续。

再按 `comic-layout.json` 的预览配置或目标观看尺寸检查：

- 主视觉与阅读顺序仍能辨认；
- 主要对白达到目标媒介要求的可读性；
- 页面密度和留白来自内容需要；
- 留白道具不会被误认成未完成占位符。

把逐只气泡和逐页结果写入 `qa/visual-review.md`。自动审计 PASS 不能代替人工 PASS。

## 文件 QA

- 页面连续命名为 `page-01.png`、`page-02.png`……；
- 最终尺寸与 `comic-layout.json` 一致；
- 文件格式和单页大小满足当前项目或平台规格；未指定大小上限时不擅自套用固定值；
- `raw/` 覆盖全部最终页，布局明确每页使用的权威原画；
- 最终页、预览和审计来自同一版布局；
- 新版本目录不残留旧页。

运行 `scripts/validate_release.py FINAL_DIR` 做结构与文件检查。它不能替代内容和视觉审核。
